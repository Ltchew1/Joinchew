Experimental · Research Floor

Inside CHEW's R&D floor.

Six experiment bays — some already running on real CHEW data, some still fixed illustrative sketches of where the intelligence system is headed. Every bay is labeled honestly, and every bay tells you plainly what it uses and what it doesn't.

Two bays below pull live from CHEW's real intelligence engine, against the same shared illustrative example used across the site. Four are fixed research sketches — fictional by design, and labeled that way in every one of their own status blocks.

Bay 01 Simulation

Parallel Futures

What would three different next moves actually cost, in time and dependency, side by side — before committing to one.

Status

Simulation — this public bay still shows a fixed, hand-built example. Nothing here is computed from a real subject on this page.

Uses
  • Real capability names from CHEW's registry, shown only as illustrative labels.
  • Internally, CHEW now has a working, deterministic multi-goal Parallel Futures engine: it compares 2–3 real paths — preserve, change a real fact, or resolve a different real requirement first — against one shared real baseline across two real goals, quantifying each path's effect where a goal's own chain supports it, and reporting an honest qualitative note (or an explicit "no declared relationship" note) everywhere else. It never picks a winner. It's gated internal-only, pending a real member identity system.
Does not yet use
  • Anyone's real facts or real requirement chain, on this public page — this bay isn't wired to that internal engine yet, so what you see here stays a fixed sketch rather than live output, to avoid implying member-specific modeling is live.

Bay 04 Experimental

Hidden Leverage

What already exists in a real subject's data that could help more than one goal, but is underused — not a fictional asset, a real fact CHEW already has.

Status

Experimental — backed by a real internal evidence-only discovery engine (lib/leverageModel.js), gated internal-only pending a real member identity system. This public bay still shows a fixed illustrative sketch, not live output.

Uses
  • Internally, CHEW has found one real leverage item in this repo's seeded data: the real documented_income fact already satisfies the home goal's real requirement, and a real, human-authored goal_conflict_rules row explicitly declares that same fact also matters to the business-funding goal — so it can be preserved and reused instead of re-established.
  • Dormant Capability detection is now real too, gated behind its own explicit capability_relevance_rules table (a human-authored row is the only way CHEW is allowed to call a capability relevant — no similarity guessing). CHEW currently has exactly one such rule, and correctly reports zero dormant capabilities right now, because this repo's provider network is genuinely empty — proven directly by temporarily seeding one real provider and watching the exact same rule correctly light up, then reverting it.
  • The engine only returns an item when it can point to real evidence (a fact id, a requirement it satisfies, a declared rule, a live provider count) — it never brainstorms or infers a relationship, asset, or program that isn't already in the schema.
Does not yet use
  • This bay isn't wired to that internal engine yet, so what you see here stays a fixed sketch rather than live output, to avoid implying member-specific modeling is live.

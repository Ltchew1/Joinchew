Bay 03 Experimental

Economic Weather

— Readiness
— Constraint Pressure
n/a Income Stability
n/a Liquidity

A real readiness reading and a real count of unresolved constraints for this scenario — plus the signals CHEW can't compute yet, marked honestly instead of guessed.

Status

Experimental — historical-state foundation active. Two of four gauges above are computed live from real data, the same as before; the deeper historical engine described below exists internally but isn't wired to this public bay yet, gated internal-only pending a real member identity system.

Uses
  • Readiness and Constraint Pressure (labeled "Risk" here previously): the real resolved/unresolved requirement fraction and the real unresolved constraints count on file for this scenario — unchanged from before.
  • Internally, CHEW now also stores real point-in-time state_snapshots of that same state, deduplicated by a real fingerprint so nothing gets recorded twice for no reason, and computes five real signals from them — Readiness, Constraint Pressure, Opportunity Access, Priority / Focus, and Capability Access. Each one honestly reports its own history depth: a single current reading with no comparison, a plain before/after change with one prior observation, or a real trend once two or more comparable snapshots exist. Never a guessed momentum score.
  • Proven directly: after a real requirement fact and a real constraint were resolved for this repo's illustrative scenario, CHEW correctly said "Readiness improved since the last observation (33% → 67%)," "Constraint Pressure eased since the last observation (1 unresolved → 0 unresolved)," and "Priority shifted from “credit_score” to “down_payment_savings_cents.”"
  • Opportunity Access now compares real canonical opportunity identity, not just a count — proven directly against the one real capability link this repo has (accounting/tax): when a real provider was replaced by a different real provider, CHEW correctly said "the count held at 1, but the real opportunities are different" (composition_changed) instead of wrongly calling it unchanged.
Does not yet use
  • Liquidity, income stability, net worth, asset growth, spending, debt, employment, cash runway, credit trend, or market exposure — none of that data exists anywhere in this schema yet, so none of it is estimated. This public bay also isn't wired to the internal historical engine yet, and snapshot-taking isn't yet triggered automatically by real portal events (a barrier resolving, an opportunity unlocking) — only on request, for now.

Bay 05 Experimental

Friction Detection

The same real requirement, seen unresolved across CHEW's own observed history — not a hunch, a pattern across real, comparable observations.

Status

Experimental — backed by real historical pattern detection, built directly on Economic Weather's state_snapshots. This public bay still shows a fixed illustrative sketch, not live output, gated internal-only pending a real member identity system.

Uses
  • Internally, CHEW now derives real friction patterns purely from real state_snapshots — no second history table, no scenario data ever counted as a real observation. Four real pattern types: a requirement staying unresolved (persistent_requirement), the same requirement staying CHEW's current focus (repeated_focus), readiness not moving while other real state changes (readiness_stall), and a requirement resolving and then genuinely becoming unmet again (recurring_requirement) — each one requiring at least 2 real comparable observations before CHEW will use the word, and escalating language only at 3 or more.
  • Proven directly: for this repo's illustrative scenario, CHEW correctly said "credit_score has remained unresolved across 3 meaningful observations," then correctly marked that same friction "resolved" once the requirement genuinely resolved, then correctly detected a real regression when it became unmet again — never inflating the count from a duplicate snapshot, never claiming a trend from a single observation.
  • Every explanation ends by naming what CHEW does not know — never a guess at motivation, avoidance, or cause.
Does not yet use
  • Any psychological interpretation, ever — CHEW can say a requirement stayed unresolved, never why. Also doesn't yet distinguish a genuine waiting period (a seasoning requirement, a scheduled review date) from real friction, since this schema stores no waiting-period data to check against — a real, named limitation, not a guess dressed up as a distinction. Nothing is persisted to a database table; every result here is derived fresh from real snapshots each time, and this public bay isn't wired to that internal engine yet.

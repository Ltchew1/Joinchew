      What This Actually Is

      Reality and simulation, computed by the same real rule — on purpose.

      Both chambers start from the exact same live fetch of requirementSequence, basedOnFacts, and capabilityOverview. Reality never changes; the Simulation chamber's toggles run through the same scenario-engine.js logic the Unlock Room uses, including the identical "first unresolved requirement, in CHEW's real order, becomes current focus" rule the real engine documents in lib/intelligenceEngine.js. Resolving a requirement that isn't already blocking anything upstream will honestly show no change to current focus — CHEW doesn't pretend order doesn't matter. Capability-coverage impact is only shown where a requirement actually links to a real capability in this example; where none do, that's stated plainly instead of a invented percentage. Nothing here writes to a database or calls CHEW's real completion path.
